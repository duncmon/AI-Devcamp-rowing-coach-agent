1. Executive Overview & Persona

The Rowing Coach Agent is an enterprise-grade artificial intelligence coaching assistant built on Google's Agent Development Kit (ADK) and the Gemini Enterprise Agent Platform. It serves Coach David Montgamery and the Masters rowing squad at Aviron Club du Lac (ACL).

Unlike generic fitness bots, the agent mathematically models rowing biomechanics (Dr. Valery Kleshnev), polarized endurance training distributions (Seiler 3-zone and 5-zone lactate models), non-linear erg/water pacing conversions (\(P \propto v^3\)), and the authoritative 13-week Phase 1 preparation curriculum targeting the Championnat Régional d'Aviron Indoor in Manosque and the Championnat de France in Paris.

3. Architectural Blueprint v0.2 Implementation

Blueprint v0.2 introduces sovereign European data protection, multi-region high availability, and zero-cost cloud persistence:

  • Decoupled Sovereign EU Boundary: Data protection layers (Model Armor, Cloud DLP byte-offset redaction, and database state) are pinned strictly to europe-west1 (Belgium), isolating athlete privacy from external jurisdictions.
  • Multi-Region Inference Router (backend/llm_router.py): Dynamic failover router cascading across global → europe-west1 → europe-west9 → us-central1 upon catching HTTP 429 quota exhaustion, injecting mandatory token preservation directives.
  • Reversible Bracketed PII Vault (backend/pii_vault.py): Replaces athlete names, domestic phones, and emails with deterministic tokens ([ATHLETE_NAME_1], [PHONE_NUMBER_1]), preserving multi-turn history while asserting zero orphan tokens on rehydration.
  • Dual-Backend Zero-Cost Persistence (backend/db.py): Automatic hybrid storage utilizing local SQLite for dev/testing and Google Cloud Firestore (Native Mode) permanent Free Tier for production deployment (fixed $0.00/mo cost floor).

5. Golden Evaluations & Fail-Closed CI/CD Release Gating

In accordance with Learning 30 and Learning 31 discovered in Lab 4:

  1. The Exit-Code 0 Trap: adk eval returns exit code 0 even when evaluations fail. Bare CI pipelines wave failing agents into production. Our release script (evals/verify_eval_gate.sh) parses Tests failed: [0-9]+ explicitly and fails closed.
  2. Mandatory Tool-Use Rubrics: Natural language response matching alone allows models to hallucinate answers while skipping tools. Our evaluation configuration (evals/eval_config.json) enforces rubric_based_tool_use_quality_v1 to prove that the agent actively loaded the rules skill and curriculum.

6. Architectural Decision Records (ADRs)

ADR-1: Pure-ASGI Middleware Redaction over Tool-Based Redaction

Decision: Scrub athlete personal data at the HTTP protocol boundary before prompt text touches the session store or model memory.

Rationale: Tool-based redaction relies on the LLM choosing to invoke the tool. If the model skips the tool, raw PII is irreversibly stored in Vertex AI durable sessions.

ADR-2: Domestic Phone Multi-Country Custom Regex Detectors

Decision: Augment Cloud DLP inspection with domestic French (0[1-9]...) and UK (020...) regex patterns.

Rationale: Cloud DLP's built-in detector rates phone numbers without international prefixes as VERY_UNLIKELY, leaking domestic contact details in conversational prompts.

ADR-3: Multi-Tier Hierarchical Configuration Resolution (POLA)

Decision: Implement 4-tier resolution in governance.py: CLI Flags → Process Environment → Local .env → ADC credentials.

Rationale: Upholds the Principle of Least Astonishment, eliminating friction and preventing abrupt terminal crashes during administration.

ADR-4: Mandatory Tool-Use Rubrics for Progressive Disclosure

Decision: Require rubric_based_tool_use_quality_v1 in all golden evaluation configs.

Rationale: Prevents silent regressions where the model answers from hallucinated memory while bypassing SkillToolset or safety tools.
