Build — Deterministic Physics, Wolverine L4 Grids & FastMCP

The core agent combines deterministic mechanical calculations with progressive LLM disclosure:

  • Concept2 Physics Engine: Computes non-linear pace-to-watts (\(W = 2.80 / (s/500)^3\)) with floating-point precision, eliminating arithmetic hallucinations.
  • Wolverine Plan Level 4 Tables: Implements stroke-rate pacing grids (@16 through @28 SPM) aligning target wattage to precise splits.
  • Dynamic Season Curriculum: Models a 13-week Phase 1 macrocycle with automated calendar evaluation and priority-based overrides.
  • Custom-Authored Intervals.icu FastMCP Server (mcp/intervals_server.py): Custom-built in Python from scratch to bridge ADK with the Intervals.icu REST API. Queries resting HR, rMSSD HRV, and ATL/CTL fatigue scores, guarded behind require_confirmation=True.

Resilient Plan Artifact Delivery & URL Encoding Defense

During live coaching runs, plan generation tools create structured markdown session sheets with rich filenames, such as Week 8 - Anaerobic & L4 Pacing (19 au 25 Octobre).md. Naive file endpoints break on encoded spaces (%20) or ampersands (%26), resulting in route truncation or HTTP 500 server crashes.

We resolved this with a hardened route in local_proxy.py:

  • Path Parameter Routing: Uses FastAPI @app.get("/api/plans/{filename:path}") to capture arbitrary path segments.
  • Entity Unquoting & Traversal Defense: Applies urllib.parse.unquote(filename) and extracts pathlib.Path(clean_name).name to strictly strip directory traversal attempts.
  • Multi-Path Resolution: Evaluates potential container storage directories across PROJECT_ROOT / "plans", Path("plans"), Path("/code/plans"), and Path("/tmp/plans"), returning a quoted Content-Disposition attachment header.
  • Fail-Safe 404 Handling: Raises a clean HTTPException(status_code=404) if the requested file is missing, completely eliminating unhandled 500 crashes.

Cloud Run Executive UI & Theme Toggle

To support coaches operating in both bright outdoor boathouses and dark indoor ergo training suites, the Cloud Run executive dashboard header features a dedicated light/dark toggle button (#theme-toggle-btn):

  • Zero-Latency DOM Switching: Synchronously modifies classList across document.documentElement and document.body (swapping bg-slate-100 text-slate-900 ↔ bg-darkbg text-slate-200) and updates #theme-icon and #theme-text without page reloads.
  • Browser LocalStorage Persistence: Automatically reads and writes preference via localStorage.getItem('rowing-coach-theme'), ensuring consistent user preference across browser sessions.

Forensic Dissection: Morning Demo Findings & Sprint Resolutions

Issue 1 — Athlete Lookup Failure on Anonymized Names: When the user typed "Coach David's UT2 Base Session", naive DLP stripping replaced the name with an opaque token ([ATHLETE_NAME_1]). The agent asked "Please provide the actual name of the athlete" because it had no link between the token and the squad roster in data/athletes.json.

Resolution: Implemented GDPR Article 9 Cryptographic Pseudonymization. The vault dynamically hashes known squad names to deterministic pseudonyms (e.g. [ATHLETE_ath_5a77195e]). Algorithmic tools (lookup_athlete, calculate_athlete_pacing) strip vault brackets and match the pseudonym to the athlete's 2k split while keeping raw personal identity 100% redacted from the LLM.
Issue 2 — The Intervals.icu Confirmation Gate Loop: When the coach attempted to stage a workout on Intervals.icu, the agent repeatedly stated "I still require your confirmation... The system is prompting for an explicit approval." even after the coach typed "I explicitly confirm".

Resolution: As shown in Figure 2.2, the deployed Reasoning Engine emits an adk_request_confirmation event. The local proxy was updated to render an interactive HTML Approval Card ([Approve & Stage Workout] / [Reject]) and automatically inject the confirmation payload back into the SSE stream.
Issue 3 — Remote Reasoning Engine Identity Mismatch & Dual-Translation Bridge: While Gate 1 vaults Coach David into cryptographic pseudonym [ATHLETE_ath_5a77195e] for GDPR Article 9 privacy, the remote Vertex AI Reasoning Engine instructions and tools index the athlete as david_montgamery (matching data/athletes.json). Direct dispatch caused entity lookup mismatches.

Resolution: Implemented a pre-dispatch translation bridge in local_proxy.py (pseudo_to_engine) that translates vaulted tokens to internal keys before sending to the engine. On egress, Gate 2 client rehydration substitutes david_montgamery back to raw_coach before running vault.rehydrate(), guaranteeing seamless coach recognition while fail-closed VaultSafetyError guards against orphan tokens.
Issue 4 — Model Armor 4-Checkpoint Architecture Verification: Traditional security quickstarts only screen direct ingress prompts, leaving the agent vulnerable to indirect prompt injection via untrusted tool outputs (e.g. scraped regatta calendars or athlete logs) and outbound data leakage.

Resolution: Formalized and verified all four lifecycle checkpoints: ① Ingress prompt screening (rowing-coach-guardrails), ② Tool Call Gate (parameter schemas & require_confirmation=True), ③ Tool Output Shield (screening untrusted external data via tool_output_template_name and research_agent sub-agent isolation), and ④ Egress SDP Redaction (rowing-coach-guardrails-output) with Gate 2 orphan token assertion. Automated regression tests verify all four checkpoints in tests/test_regression_fixes.py.
