Section 3

GDPR Article 9 & Cryptographic Pseudonym Architecture

Under European Union law (GDPR Article 9), physiological metrics, heart-rate zones, resting HRV, and injury notes are classified as Special Category Health Data. Processing this data requires explicit safeguards:

  1. Zero PII in Model Weights or Cloud Logs: Real names, telephone numbers, and email addresses are replaced at the ASGI boundary before prompts touch Vertex AI or Google Cloud Logging.
  2. Cryptographic Pseudonymization: Rather than assigning random tokens like [ATHLETE_NAME_1] (which destroys context and prevents the agent from opening the rower's file), the vault computes deterministic SHA-256 tokens matching the squad database in data/athletes.json (e.g. [ATHLETE_ath_5a77195e] for David Montgomery).
  3. Algorithmic Tool Unwrapping: When the orchestrator delegates to deterministic physics or Wolverine L4 calculation tools (calculate_athlete_pacing, align_session_pace_to_l4), the tool code unwraps the pseudonym to access benchmark splits, returning calibrated target wattages and splits to the model.
  4. Gate 2 Reversible Client Rehydration: On the egress boundary, Gate 2 restores the athlete's friendly name for the coach's browser display, while asserting zero unmapped orphan tokens (VaultSafetyError).
